## D1 — Normalization & preprocessing
**Script:** `analyze_entropy.R` (calls `R/spanorm_lowmem.R`, `R/gene_universe.R`, `R/shannon_entropy.R`)
**Decision:** Raw Visium spatial transcriptomics data are loaded from `data/<sample_name>/`. Spots are explicitly subsetted to in-tissue spots (`in_tissue == 1`) using `spatial/tissue_positions.csv` *before* applying depth quality control. Visium hexagonal array lattice coordinates (`array_row` and `array_col`) are extracted from `tissue_positions.csv` and stored in the Seurat object's metadata for downstream spatial neighborhood construction (Stage 4). Spots are filtered on a minimum sequencing depth of $nCount \ge 500$ and a minimum feature count of $nFeature \ge 250$, followed by coordinate alignment verification via `validate_imaged_coordinates()`. Features are filtered directly against the cohort Gene Universe (`results/cohort_qc/gene_universe.csv`, D5, 18,532 features in Seurat) without per-sample detection thresholding. Normalization is performed directly via `SpaNorm::SpaNorm()` using negative binomial modeling (`gene.model = "nb"`), `adj.method = "logpac"`, `df.tps = 6`, `lambda.a = 1e-04`, a fixed random seed (`set.seed(23)`), and default sampling fraction (`sample.p = 0.25`). An S4 method for `SpaNorm::SpaNorm` is registered on `Seurat` objects using public Bioconductor APIs (`SpatialExperiment` and `SummarizedExperiment`), eliminating private `:::` function calls. SpaNorm is the normalized input for downstream differential expression, module scoring, and visualization, and is also the layer the second entropy baseline is computed on (D2). QC metrics with explicit denominators (`Raw_Spots_Grid`, `Spots_On_Tissue`, `Spots_Post_Depth_QC`, `Spots_Post_Coord_Validation`, `Spots_Final`, `Pct_OnTissue_Retained`, `Raw_Genes`, `Genes_In_Universe`, `Genes_Detected`, `Pct_Universe_Detected`, `Mean_Percent_MT`, `Mean_Percent_Ribo`) along with entropy distribution metrics (`Mean_Raw_Plugin_Entropy`, `SD_Raw_Plugin_Entropy`, `Median_Raw_Plugin_Entropy`, `IQR_Raw_Plugin_Entropy`, `Min_Raw_Plugin_Entropy`, `Max_Raw_Plugin_Entropy`, `Range_Raw_Plugin_Entropy`) are logged per sample to `results/analyze_entropy/<sample_name>_qc_metrics.csv`.
**Rationale:** `Load10X_Spatial(filter.matrix = TRUE)` filters the image, not the counts matrix, so the object retains all 14,336 grid barcodes when reading raw feature matrices. Explicitly subsetting on `in_tissue == 1` before depth QC ensures that QC denominators reflect true tissue area rather than unutilised slide background (2,623 off-tissue barcodes in sample1). The $nCount \ge 500$ and $nFeature \ge 250$ thresholds are plain quality floors: they remove barcodes too sparse to carry a usable expression profile at all, and are deliberately *not* tied to any estimator's target depth, so that changing the entropy formulation does not silently change which tissue is analysed. Dropping the per-sample detection filter (previously $\max(20, \lceil 0.02 \times N_{\text{valid\_spots}} \rceil)$) ensures that every sample across the cohort is processed on the exact same feature space (the 18,532 universe genes), preventing sample-specific gene attrition from distorting cross-sample comparisons; rare zero/low-count genes contribute minimally to entropy either way. SpaNorm removes technical spatial noise and sequencing depth confounders while preserving spatial tissue architecture.
**Alternatives considered / rejected:** SCTransform and standard log-normalization were rejected because they do not explicitly model spatial coordinates or adjust for spatial technical autocorrelation. Keeping per-sample detection thresholding was rejected because varying gene sets across samples break cohort-wide comparability and complicate feature accounting. Removing SpaNorm entirely was rejected: SpaNorm remains essential for gene-level spatial differential expression, module scoring, and expression visualization. **Coupling the spot QC floor to the entropy estimator was rejected** along with rarefaction itself (D2): the previous revision set $nCount \ge 2000$ to match the rarefaction depth $D = 2000$ and added a second gate on the post-exclusion entropy-matrix depth, which made a quality threshold hostage to an estimator choice and discarded a very uneven share of each sample's tissue (sample1 0.4%, sample4 18.5%, sample21 31.9%) in the service of a metric that is no longer used.
**Status:** implemented
**Review notes:** Reverted the spot QC floor to $nCount \ge 500$, $nFeature \ge 250$ and removed the second (post-exclusion) depth gate together with its `Spots_Dropped_Entropy_Depth` QC column, when rarefaction was dropped (D2). The seven entropy distribution columns were renamed from `*_Rarefied_Entropy` to `*_Raw_Plugin_Entropy`. Array lattice coordinates (`array_row`, `array_col`) are in metadata. The per-sample 2% spot detection threshold stays dropped, freezing the feature set to the cohort gene universe as-is (18,532 features in Seurat). Integrated cohort gene universe filtering (`filter_by_gene_universe()`). Replaced internal `:::` fitting architecture with direct `SpaNorm::SpaNorm()` method dispatch on `Seurat` objects. Pinned `bioconductor-spanorm=1.4.0=r45hdfd78af_0` and `bioconductor-spatialexperiment=1.20.0=r45hdfd78af_0` in `environment.yml`. The per-sample spot counts recorded elsewhere in this file predate the QC revision and need re-measuring on the next cohort run.

Memory note (implementation only, output unchanged): `SpaNorm:::normaliseLogPAC()` builds the whole $n_{\text{genes}} \times n_{\text{cells}}$ adjustment in a single expression, keeping roughly ten dense double matrices alive at once (`mu`, `mu.2`, two densified copies of the counts, `lb`, `ub`, `p`, and the `pmin`/`pmax`, `qnbinom` and `log2` temporaries). At sample1's dimensions one such matrix is 1.36 GB, so the step peaks near 13.6 GB and the OOM killer fires on a 15.1 GB machine. `R/spanorm_lowmem.R` supplies `normaliseLogPAC_lowmem()`, which performs the identical arithmetic in blocks of genes and writes into a preallocated output matrix; `enable_spanorm_lowmem()` installs it into the SpaNorm namespace via `assignInNamespace()` at the top of `analyze_entropy.R`. This is exact rather than approximate: given the fitted model every operation in the original is row-wise, and the single cross-gene quantity, `psi.max` = $\exp(\mathrm{median}(\log \psi) + 3\,\mathrm{mad}(\log \psi))$, is computed from the complete $\psi$ vector before any chunking. Verified with `identical()` against the unpatched kernel on a synthetic $700 \times 400$ fit at block sizes of 700, 125 and 1 genes, and end-to-end through `SpaNorm::SpaNorm()`; all four comparisons returned `TRUE` with a maximum absolute difference of 0. The public `SpaNorm::SpaNorm()` call, the model fit, `sample.p`, and every methodological parameter in this decision are untouched, and no package was added, removed or upgraded. The `logcounts` handoff in the `Seurat` method was also reordered to drop the `SpatialExperiment` reference before the dense-to-sparse conversion, so the dense and sparse representations are never alive at the same time. Measured on sample1 with `VmHWM`: whole-run peak RSS fell from an aborted run to 10.07 GB with this patch alone, and to 7.59 GB once the entropy helper was blocked as well (D2).

## D2 — Shannon entropy formulation
**Script:** `R/shannon_entropy.R` (called from `analyze_entropy.R`, `diagnose_entropy_scaling.R`)
**Decision:** Spot-level transcriptional diversity is quantified with the **plug-in Shannon entropy** estimator, $H_j = -\sum_i p_{ij} \log_2 p_{ij}$ with $p_{ij} = y_{ij} / \sum_i y_{ij}$, evaluated on two layers and stored as two metadata columns:

1. `entropy_raw_plugin` — computed on the raw counts layer at each spot's own full depth. This is the primary column carried into the QC tables, the spatial plot and the stemness correlations.
2. `entropy_spanorm_plugin` — computed on the SpaNorm `logpac` `data` layer, after normalization, as a reference point.

Prior to estimation, mitochondrial (`^MT-`) and ribosomal (`^RP[SL]`) gene families are dropped from the matrix via `exclude_pattern = "^(MT-|RP[SL])"`. Both columns come from the same helper, `calculate_shannon_entropy()`, which wraps the column-blocked sparse kernel `plugin_entropy_matrix()` so that peak memory is bounded by a non-zero budget rather than by the size of the matrix. No alias column named `shannon_entropy` is written: that name previously denoted the SpaNorm log-scale entropy, and reusing it would silently relabel a metric this file has already characterised as defective.

**Both columns are known-biased baselines, not committed metrics.** They are what the pipeline carries while a replacement estimator is designed, and each has a measured defect recorded below. Any candidate replacement is judged against both.

**Rationale:** Two distinct defects were diagnosed in Stage 2 and they are not the same problem.

*The log transform.* Computing entropy on SpaNorm `logpac` output is a category error: the $\log_2(\text{qnbinom}(\cdot) + 1)$ compression flattens the relative proportions $p_i \to 1/K$, so the resulting entropy degenerates onto $\log_2(K)$, where $K$ is the number of genes with a non-zero normalized value ($r = 0.9986$, $\rho = 0.9989$ in sample1). On that layer the metric is a relabelled gene counter. This is why `entropy_spanorm_plugin` is recorded as a reference point rather than used as the metric, and it is measured, not assumed — `diagnose_entropy_scaling.R` emits the fit.

*The depth-driven support ceiling.* Unrarefied raw counts carry a mechanical depth bias: a spot sequenced to 3,000 counts can observe at most ~2,000 distinct genes, so its plug-in entropy is capped near $\log_2(2000)$ regardless of biological state ($\rho = 0.7311$ vs $nCount$, $\rho = 0.8187$ vs $nFeature$ in sample1). Linear back-transformation ($2^x - 1$) fixes the first defect but inherits this one ($\rho = 0.7540$ vs $nFeature$). `entropy_raw_plugin` carries this bias openly; it is the defect the replacement estimator has to address.

**Alternatives considered / rejected:**
1. *SpaNorm log-scale entropy as the primary metric:* Rejected due to complete degeneracy ($r = 0.9986$ against $\log_2 K$). Retained only as the `entropy_spanorm_plugin` reference column.
2. *Linear back-transformation ($2^x - 1$) without further correction:* Rejected because it inherits the raw depth-driven support ceiling ($\rho = 0.7540$ vs $nFeature$, $\rho = 0.8602$ vs imputed support $n\_detected\_norm$).
3. **Rarefaction (implemented, evaluated, and set aside).** A rarefied estimator was built and run: counts downsampled to a fixed depth $D = 2000$ via `scuttle::downsampleMatrix(counts, prop = D / N, bycol = TRUE)`, averaged over $n_{\text{draws}} = 5$ draws. It did what it was designed to do — the near-deterministic detected-gene coupling collapsed ($\rho = -0.1330$ vs $nFeature$, $-0.2518$ vs $nCount$ in sample1) — but it is not the route this project follows, for the reasons below, and it has been removed from the pipeline. The estimator, its Seurat wrapper and the depth sweep that chose $D$ are preserved in the standalone script `rarefaction_entropy.R`, which nothing in the pipeline sources; the sweep outputs remain under `results/rarefaction/`. Its costs: it discards data by construction; it forced a depth-coupled spot QC threshold that removed an uneven share of each sample's tissue (0.4% of sample1 but 31.9% of sample21, leaving each sample with a differently-holed hex lattice, D1/D6); its dynamic range is narrow (sample1 $SD = 0.0898$ against a mean of $10.2278$, a coefficient of variation under 1%); and it introduced a positive association with `percent.mt` ($r = +0.3291$) larger than the biological association it was meant to license, consistent with degraded spots reading as flatter and therefore more diverse at fixed $D$. The relevant literature is recorded for the write-up: the standard objection, "Rarefying is inadmissible" (McMurdie & Holmes 2014), concerns differential abundance testing rather than alpha-diversity estimation and does *not* apply here — rarefaction was set aside on the grounds above, not on that critique.
4. *Bias-corrected estimators (Miller–Madow, Chao–Shen, James–Stein) and coverage-based standardisation / Hill numbers (Chao & Jost 2012):* **Three are now implemented and enter the Stage A bake-off; none is yet chosen.** `R/shannon_entropy.R` provides `entropy_estimator_matrix()`, a single column-blocked sparse kernel that computes the per-spot count statistics $N$, $K$, $f_1$, $f_2$ and every requested estimator in one pass, and `calculate_entropy()`, the Seurat wrapper over it:

   * **Chao–Shen** (Chao & Shen 2003), the primary candidate. Good–Turing coverage $C = 1 - f_1/N$, adjusted probabilities $\tilde{p}_i = C \cdot y_i / N$ over observed genes only, and a Horvitz–Thompson inclusion correction that up-weights each observed gene by one over its probability of having been seen at all: $H_{CS} = -\sum_i \tilde{p}_i \log_2 \tilde{p}_i \,/\, [1 - (1-\tilde{p}_i)^N]$.
   * **Chao–Shen with Chao–Wang–Jost coverage**, secondary candidate: the same estimator with $C = 1 - (f_1/N)\left[(N-1)f_1 / ((N-1)f_1 + 2f_2)\right]$, which uses the doubletons. $f_2$ is free once $f_1$ is being computed. **The label must not overclaim:** this is Chao–Shen with an improved coverage term, *not* the full Chao–Wang–Jost (2013) entropy estimator, which is a distinct and more involved formula.
   * **Miller–Madow**, third comparator: $H_{MM} = H_{\text{plug-in}} + (K-1)/(2N\ln 2)$. The $\ln 2$ is not optional — the correction is derived in nats and this metric is in bits; an earlier draft of this argument stated it in nats against a bits-valued metric and thereby overstated it by a factor of $1/\ln 2$.
   * James–Stein shrinkage and Hill-number / coverage-based standardisation remain unevaluated. They stay open, but they are not in the current bake-off: the three above bracket the correction-aggressiveness range that matters here (Miller–Madow corrects least, Chao–Shen most), and adding a fourth axis before the first three have been measured would widen the pre-registered criterion rather than test it.

   Three numerical decisions are load-bearing and are recorded so they are not "simplified" later. (a) The inclusion probability is evaluated as `-expm1(N * log1p(-p_tilde))` rather than the algebraically equivalent `1 - (1-p)^N`: at $\tilde{p} \sim 10^{-4}$ and $N \sim 10^{4}$, which is exactly this dataset's regime, the naive form loses most of its significant digits. (b) $f_1 = N$ (every observed gene a singleton) drives $C$ to zero and the estimator to total degeneracy, so the standard $f_1 := N-1$ substitution is applied; the CWJ bracket additionally resolves $0/0$ to a zero correction ($C = 1$) when $f_1 = f_2 = 0$. Both cases are rare at Visium depths but occur in the shallow tail, and an unguarded `NaN` reaches a spatial plot before it reaches anyone's attention. (c) The kernel calls `Matrix::drop0()` before reading the sparse slots and **asserts that the matrix is integer-valued and non-negative**. `diff(@p)` counts stored entries rather than non-zero entries, and Seurat's `subset()` and the gene-universe filter both leave explicit zeros behind, so $K$, $f_1$ and $f_2$ are silently wrong without the drop — wrong specifically for the shallow spots the correction exists to rescue. The integrality assertion exists because $f_1$ and $f_2$ are counts of singleton and doubleton *reads* and are meaningless on a rescaled matrix; pointing an entropy estimator at a normalized layer is the category error that produced the `entropy_spanorm_plugin` defect above, and the kernel now refuses instead of returning a plausible number.

   An **ordering invariant** is enforced by `check_entropy_ordering()`: both corrections are upward, so $H_{\text{plug-in}} \le H_{MM}$ and $H_{\text{plug-in}} \le H_{CS}$ hold by construction and a violation is a bug. $H_{MM} \le H_{CS}$ is **not** a theorem and is reported rather than asserted — 5 of the 22 validation fixtures violate it, being every fixture with $f_1 = 0$ plus one with a light singleton tail. Miller–Madow's correction depends only on $K/N$ and grows with the observed support, whereas Chao–Shen's is driven by $f_1/N$ and vanishes as coverage approaches 1. An implementation asserting the full chain would report a bug on correct output.

**Pre-registered acceptance criterion for the replacement estimator (Stage A0, frozen before any estimator diagnostic was run).**

D6 forbids choosing a threshold after seeing the result it gates, and the rarefaction episode showed that a depth correction can look successful on one number while failing on another: rarefaction collapsed the depth coupling exactly as designed and was still set aside, because its dynamic range and its `percent.mt` association were not examined until afterwards. The same discipline is therefore applied to the estimator. The five criteria below were written into this file before `diagnose_entropy_scaling.R` was rewritten and before any candidate estimator was evaluated on real data. They are evaluated on the three diagnostic samples spanning the cohort depth range — `sample1` (deep), `sample4` (moderate), `sample21` (shallow) — and a candidate must satisfy all five on all three.

1. **Depth decoupling.** $|\rho(H, nCount)| < 0.30$ and $|\rho(H, nFeature)| < 0.30$, Spearman, on each of the three samples. The bound is deliberately not zero: sequencing depth partly tracks the number of cells under a spot, and more cells genuinely means more distinct transcriptional programs, so an estimator forced to zero correlation with depth would be removing biology along with the artefact. This is the "substantially reduced, no longer near-deterministic" standard, set against the plug-in baseline's $\rho = 0.7311$ vs $nCount$ and $0.8187$ vs $nFeature$.

2. **No sign flip.** The correlation must not cross zero into moderate negative territory; concretely, $\rho(H, nFeature) > -0.15$ on all three samples. Rarefaction moved this statistic from $+0.72$ to $-0.23$, and that sign change was the tell that a new artefact had been introduced rather than an old one removed. An estimator that over-corrects makes shallow spots look *more* diverse than deep ones, which is not a defensible position for a diversity metric.

3. **Subsampling stability.** With every spot downsampled by a common proportion (Stage A4), the median $|H(50\%) - H(100\%)|$ must be under 20% of the estimator's own between-spot standard deviation at full depth. ~~and the Spearman rank correlation between the 50% and 100% values must exceed 0.90~~ — **the rank half is retired; see "Two retired criterion halves" below.** An estimator that is genuinely depth-unbiased returns approximately the same value when every spot's depth is halved; one that is not drops systematically. The ratio form is used rather than an absolute number of bits because the estimators do not share a scale.

4. **Dynamic range.** ~~Between-spot coefficient of variation $SD/\text{mean} \ge 0.02$ and~~ $IQR \ge 0.10$ bits, on each of the three samples — **the CV half is retired; see "Two retired criterion halves" below.** This is the criterion rarefaction failed silently: $SD = 0.0898$ on a mean of $10.2278$ is a CV of 0.88%, and a metric with no spread between spots cannot correlate with anything, however correctly its bias is removed. The floor is set at rather more than twice the observed failure so that passing it means something; it is a usability floor, not a target.

5. **`percent.mt` association does not worsen.** Checked in two places, because the two forms become available at different stages. (a) *At A3, against the baseline:* $|r(H_{\text{candidate}}, \texttt{percent.mt})|$ must not exceed $|r(H_{\text{plugin}}, \texttt{percent.mt})|$ measured on the same spots by more than 0.10. This is the form that would have caught rarefaction, whose $r = +0.3291$ was the disqualifying number, and it is checkable inside A3's own output without any downstream input. (b) *At A5/Stage C, against the biology:* the `percent.mt` association must not be larger than the entropy–`Stemness_Score1` association, and the association must survive the $\log(nCount)$ + `percent.mt` partial and hold across `percent.mt` quartiles. This second form needs `Stemness_Score1`, which `analyze_stemness.R` produces downstream of the estimator, so it cannot be evaluated at A3; it runs through `run_quality_confound_check()` in `R/quality_confound.R` unchanged (D3).

Criteria 1, 2, 4 and 5(a) are evaluated from `results/statistical_tests/<sample>_estimator_comparison.csv` (Stage A3); criterion 3 from the Stage A4 subsampling ladder; criterion 5(b) at Stage C. If no candidate clears all five, the documented fallback is to keep the plug-in estimator and move the correction from the metric to the inference, making the depth-adjusted partial correlation the headline number everywhere — weaker, but honest, and supported by the agreement already recorded in D3 between the rarefied metric and the $\log(nCount)$-partialled plug-in metric.

### Stage A5 — the decision, and what was fixed before it

A3 and A4 left A5 between two of the three branches the pivot plan wrote for it, not on one of them. Branch 1 (Chao–Shen passes cleanly) is not satisfied. Branch 2 (overcorrection) is definitively not satisfied — no sign flip on any sample, `percent.mt` improved rather than merely held, and Chao–Shen-with-CWJ-coverage tracks plain Chao–Shen to 3–4 decimals while Miller–Madow barely corrects at all. Branch 3's *trigger* ("nothing decouples adequately") is satisfied, but its *prescription* — keep the plug-in and move the correction to the inference stage — contains a non-sequitur: if the endpoint is a depth-adjusted partial either way, adjusting a metric that starts at $\rho = 0.98$ is a harder ask than adjusting one at $\rho = 0.02$–$0.58$, not a safer one.

Two arguments cut against each other and neither was measured at A3/A4:

- *For the metric-side route.* Chao–Shen corrects the actual mechanism — undersampling of the gene support — not "depth" generically. A $\log(nCount)$ partial also removes depth-correlated **biology**: more cells under a spot genuinely means more transcriptional programs, which is exactly why criterion 1's bound was set at 0.30 rather than at zero. Suggestively, sample4 is where Chao–Shen decouples worst ($\rho = 0.558$) despite having the *lowest* median Good–Turing coverage of the three diagnostic samples (0.689, against sample21's 0.723) — consistent with part of sample4's residual entropy–depth link being real rather than artefactual.
- *For the inference-side route.* The depth-free split-half above shows the plug-in's depth-partialled residual is **more** reliable (0.971–0.973) than Chao–Shen's (0.898–0.959). If both end up partialled anyway, Chao–Shen's precision cost buys nothing.

**A5a — the measurement that adjudicates them.** `diagnose_correction_routes.R`. Route M's depth-corrected object is `chao_shen` itself; Route I's is the plug-in residualised on $\log(nCount)$. If those two objects rank spots the same way, the routes are doing the same work and the choice is low-stakes; if they diverge, one has to be argued for. This is the metric-level analogue of the hypothesis D3 records from the rarefaction era, and it needs no `Stemness_Score1`, so it is answerable now rather than at Stage C. It is paired with a second measurement, because a high agreement would settle nothing if Route I's residual still carried depth: entropy saturates logarithmically in $N$, so a *linear* $\log(nCount)$ term can leave curvature behind, and each estimator's residual is therefore also regressed on `splines::ns(log(nCount), df = 4)` — the $R^2$ of that fit is residual depth structure the linear adjustment did not reach. `splines` is base R; no new dependency. The reliability half is **read from** `<sample>_subsampling_reliability.csv`, not recomputed.

**The A5a decision rule, fixed before the script was first run** — recorded here for the same reason the A0 criteria were, and in the same spirit as D6's rejected alternative 1:

- **Routes agree** — $\rho(\text{Route M}, \text{Route I}) \ge 0.80$ on $\ge 12$ of 16 cohort samples $\Rightarrow$ the routes correct the same thing. Adopt Chao–Shen as the primary metric with the plug-in co-reported, and record the agreement itself as a robustness result.
- **Routes diverge** — $\rho < 0.80$ on more than 4 samples $\Rightarrow$ not the same correction; the residual depth structure decides which route to believe.
- **Independently of the above** — if the plug-in's linearly-partialled residual keeps spline $R^2 > 0.05$ on a majority of samples while Chao–Shen's stays below it, linear partialling under-corrects and the metric-side correction is required regardless of the agreement verdict.

The 0.80 and 0.05 are set a priori. A result landing near a boundary is reported as near-boundary; it is not re-thresholded. The constants live at the top of `diagnose_correction_routes.R` and are read from there.

**A5b — cohort scope.** Committing a metric on $n = 3$ is thin, and the per-sample spread is already large (criterion 1 passes on sample21 and fails on sample4). A3, A4 and A5a all gained an `--all` flag driving the frozen 16-sample cohort through `cohort_samples()` (`R/diagnostic_sweep.R`). This is affordable only because none of them runs SpaNorm — the same blocker solved at A3. Criterion outcomes are reported as **"passes on $k$ of 16"**; the $k/16$ counts are evidence to read, not a threshold to tune.

### Pre-registered for Stage C: criterion 5(b) and the D3 confirmatory check

Written here **before** Stage C produces any stemness number. Criterion 5(b) is the one A0 criterion A5 cannot evaluate, and it is the one that can still bite.

1. **Criterion 5(b), against the biology.** $|r(\texttt{entropy\_chao\_shen}, \texttt{percent.mt})|$ must be smaller than $|r(\texttt{entropy\_chao\_shen}, \texttt{Stemness\_Score1})|$; the partial given $\log(nCount)$ + `percent.mt` must keep the same sign and remain significant; and the association must hold with consistent sign in at least 3 of the 4 `percent.mt` quartiles. All three read off `run_quality_confound_check()` (`R/quality_confound.R`) unchanged — parts (a), (b) and (c) respectively.
2. **The D3 confirmatory check.** $\rho(\texttt{entropy\_chao\_shen}, \texttt{Stemness\_Score1})$ and the rank-partial $\rho(\texttt{entropy\_raw\_plugin}, \texttt{Stemness\_Score1} \mid \log(nCount))$ must agree in sign and differ by no more than 0.10 — the same tolerance form as criterion 5(a). This is the cohort-scale replication of the rarefaction-era observation recorded at the end of D3 ($r = +0.0083 \to +0.1594$, $\rho = +0.0472 \to +0.2013$ on sample1), which that entry carries explicitly as a hypothesis rather than a result.
3. **Consequence of failure, stated now.** If the two disagree, this decision reverts from `implemented` to `provisional` and the thesis reports both correction routes side by side rather than headlining one. Recording the consequence in advance is what stops the criterion from being argued away once the numbers exist.

### Stage A5 results — the 16-sample cohort

Everything above this heading was measured on three diagnostic samples. All of it was re-run across the frozen 16-sample cohort (D6), 16/16 on each of A3, A4 and A5a with no failures. **Where the cohort and the three-sample numbers disagree, the cohort numbers are the record.** They disagree in two places that matter.

**The plug-in baseline is far worse than this entry has been quoting.** Its $\rho$ against $nCount$ has a cohort median of **0.825** and a range of 0.468–0.977. Criterion 1's bound was calibrated against sample1's 0.7311, and sample1 turns out to be among the *better* samples. The plug-in fails criterion 1 on **16 of 16**.

| criterion 1 (both $|\rho| < 0.30$) | passes |
|---|---|
| plug-in | **0 / 16** |
| Miller–Madow | 1 / 16 |
| Chao–Shen | **6 / 16** |
| Chao–Shen (CWJ coverage) | 6 / 16 |

**A5a — the routes diverge.** $\rho(\text{Route M}, \text{Route I}) \ge 0.80$ on only **7 of 16** (median 0.762, range 0.508–0.897), against the pre-registered requirement of $\ge 12$. The metric-side and inference-side corrections are therefore **not** doing the same work, and by the rule fixed before the run the residual depth structure decides.

**It decides emphatically.** Spline $R^2$ of each estimator's residual on $\log(nCount)$ *after* the linear term has been removed — i.e. depth structure the inference-side adjustment cannot reach:

| | median | range | above 0.05 |
|---|---|---|---|
| plug-in | **0.597** | 0.172–0.786 | **16 / 16** |
| Miller–Madow | 0.566 | 0.177–0.766 | 16 / 16 |
| Chao–Shen | **0.044** | 0.005–0.369 | 8 / 16 |

Roughly **60% of the plug-in residual's variance is still depth** once the $\log(nCount)$ partial has done its work. Branch 3 of the pivot plan — keep the plug-in and correct at the inference stage — is therefore not an equivalent substitute for a better estimator; it is a substantially weaker correction, and the third clause of the A5a rule fires without ambiguity.

This also disposes of the strongest argument that had favoured the inference-side route. The plug-in's depth-partialled residual *is* more reliable than Chao–Shen's (0.976 vs 0.956 median). But a large part of what remains in it is still depth, and depth is exactly what reproduces under common-proportion thinning. It is reliable partly because it is still measuring the confounder — the same failure mode as the retired rank half of criterion 3, in different clothes.

**Miller–Madow is finished.** Its partial correlation with the plug-in, both adjusted for depth, has a cohort median of **0.969**: once you take the partial it *is* the plug-in. Chao–Shen's 0.860 (range 0.585–0.945) means it carries structure the partial cannot reach. Chao–Shen-with-CWJ-coverage continues to track plain Chao–Shen to 3–4 decimals on every statistic and is not a distinguishable candidate at these depths; both stay reachable through the `estimator =` argument of `calculate_entropy()` and are computed by every diagnostic, but neither is carried in the pipeline.

**The ordering invariants, at cohort scale.** Across all **142,960 spots** of the 16-sample cohort: $H_{\text{plugin}} \le H_{\text{CS}}$, $H_{\text{plugin}} \le H_{\text{CS-CWJ}}$ and $H_{\text{plugin}} \le H_{\text{MM}}$ hold with **zero** violations, while $H_{\text{MM}} \le H_{\text{CS}}$ — which the pivot plan asserted as part of a single ordering chain — is violated **12 times**. The A2 correction that demoted it from an assertion to a reported-only comparison is what allowed the sweep to run at all; asserting the full chain would have aborted it.

**A4 across the cohort.** Chao–Shen removes a median **54%** of the plug-in's depth bias (range 48–67%), reproducing the three-sample finding at cohort scale. Criterion 3's magnitude half fails **0/16 for every estimator**, and — worth naming — the *ratios* are near-identical across estimators (0.563 plug-in, 0.528 Miller–Madow, 0.560 Chao–Shen) even though the absolute bias differs twofold (median signed $\Delta H$ of $-0.312$ against $-0.156$). Because Chao–Shen shrinks the between-spot SD as well as the bias, the ratio form cancels its own improvement. That is not a reason to retire the criterion — "is the bias large relative to the biological spread you are trying to detect" is a fair question, and the answer is yes for everything — but it does mean criterion 3 **does not discriminate between candidates**. With criterion 4 passing everywhere and criterion 2 passing everywhere, three of the five A0 criteria separate nothing. Criterion 1 and the descriptive measures are what carry the decision.

The depth-free split-half reliability behaves correctly at cohort scale, both reference rows included: pure depth **+0.012**, independent noise **−0.004**, plug-in **0.976**, Miller–Madow 0.978, Chao–Shen **0.956**. Chao–Shen's precision cost is ~0.02 in the median — appreciably smaller than the three-sample run suggested, where sample4's 0.898 was an outlier rather than typical.

### The finding that cuts against Chao–Shen, and why it did not overturn the decision

Chao–Shen fails criterion 5(a) on 2 of 16 samples, and the failures are not scatter. It pushes the `percent.mt` association **upward on every sample**. Where the plug-in had a strong negative association (14 samples, $-0.30$ to $-0.81$) that cancels toward zero, which is the improvement recorded in the three-sample section above. On the two samples where the plug-in had essentially none — sample5 ($-0.055$) and sample18 ($+0.006$) — the same push overshoots to **$+0.443$ and $+0.265$**. For scale, rarefaction's disqualifying number in this entry is $r = +0.3291$.

The mechanism is the correction term itself. Degraded, high-`percent.mt` spots have flat, ambient-like profiles (D6), which means more singletons, a larger $f_1/N$, and a larger upward correction. **Chao–Shen removes the depth artefact and amplifies the degradation artefact.**

Two things had to be checked before treating that as decisive, and they pull in opposite directions.

*First, criterion 5(a) is blind to sign.* It is written as $|r_{\text{cand}}| \le |r_{\text{plugin}}| + 0.10$, purely relative. On sample7 the plug-in is $-0.803$ and Chao–Shen is $+0.454$ — a sign flip to a large positive association — which **passes**, because the plug-in was worse in absolute value. Criterion 2's no-sign-flip clause covers only $\rho$ against $nFeature$, not the MT association, so nothing in A0 catches this. Unlike the two retired criterion halves, 5(a) is not invalid — it is incomplete, so it stays as written and the absolute magnitudes are reported beside it rather than replacing it.

*Second, and against Chao–Shen: the zero-order comparison flatters the plug-in.* On sample5 the plug-in's near-zero $r = -0.055$ is a **cancellation**, not an absence: with depth removed it becomes $+0.397$. The plug-in's depth bias runs opposite to a real H–MT relation and the two offset, so criterion 5(a) at zero order credits it for having two artefacts that happen to hide each other.

That raised the possibility that Chao–Shen's apparent MT disadvantage was itself an artefact of an unfair comparison — the linear partial removes most of Chao–Shen's depth but little of the plug-in's (0.044 against 0.597 above), and since `percent.mt` is coupled to depth (cohort $\rho = -0.41$, Stage 0) the plug-in's leftover depth would leak into its MT partial and suppress it. **That hypothesis was tested and did not hold.** Adjusting both estimators on the same spline basis of $\log(nCount)$ — the fair comparison — moves the plug-in's median $|r|$ from 0.183 to 0.222 as predicted, and leaves the conclusion intact:

| $|r(H, \texttt{percent.mt})|$ | zero-order | linear partial | **spline partial** | $> 0.329$ |
|---|---|---|---|---|
| plug-in | 0.466 | 0.183 | **0.222** | 4 / 16 |
| Miller–Madow | 0.384 | 0.156 | 0.249 | 4 / 16 |
| Chao–Shen | 0.171 | 0.276 | **0.262** | **7 / 16** |

Chao–Shen is worse on **12 of 16** under the fair test (slightly *more* than the 11/16 under the unfair one), and its spline-adjusted association is **positive on 14 of 16** — a consistent direction, which is the signature of a mechanism rather than of scatter. The plug-in's is mixed in sign (7 positive, 9 negative). This is a real cost, established on a fair comparison, and it is not an artefact of any criterion.

**The decision.** Chao–Shen is adopted as the primary metric with the plug-in co-reported. The reasoning, stated so it can be argued with:

1. Depth coupling is the defect this whole pivot exists to fix, the plug-in fails criterion 1 on 16/16, and A5a shows the inference-side alternative leaves ~60% of that structure in place. There is no version of "keep the plug-in" that addresses the original problem.
2. The MT cost is bounded (0.262 against 0.222 in the median) and its consequences are measured against biology, not against another artefact — which is exactly what the pre-registered criterion 5(b) does at Stage C. It is gated, not ignored.
3. Co-reporting `entropy_raw_plugin` costs one column and one blocked pass, and means that if 5(b) fails for Chao–Shen the comparison is already in hand rather than needing a re-run.
4. Miller–Madow and CWJ are not alternatives: the first is the plug-in once adjusted, the second is Chao–Shen to four decimals.

**This is a trade, not a clean win, and the write-up must say so.** Chao–Shen removes most of a large artefact and adds part of a smaller one. If criterion 5(b) fails at Stage C the pre-registered consequence above applies unchanged.

**Two retired criterion halves.** Two of the five A0 criteria were written with a second, redundant-looking clause that turned out to be measuring the wrong thing. Both clauses are retired. Retiring them is *not* the threshold-shopping D6 forbids, and the distinction matters enough to state precisely: a threshold is revised when a number is moved so that a preferred candidate passes; a criterion is retired when the statistic it computes can be shown, **without reference to which estimator wins**, not to measure the property the criterion names. Both retirements below meet the second test, are demonstrated by a measurement that involves no estimator at all, and neither changes any estimator's overall A3/A4 verdict. *Retired: the rank half of criterion 3 ($\rho_{\text{Spearman}}(H_{50\%}, H_{100\%}) > 0.90$).* Common-proportion thinning preserves the relative depth ordering of the spots almost exactly — the binomial noise on a spot's total is $\approx 0.5\sqrt{N}$, negligible against the spread of $N$ across spots. Any metric that is a monotone function of depth therefore reproduces its own ranks under thinning. `diagnose_subsampling_stability.R` now measures this ceiling directly by using each spot's own total counts as a pseudo-metric:

Two things follow, and they cut in opposite directions. First, **the precision cost of Chao–Shen is real and survives the correction of the criterion**: it loses 0.05–0.07 of depth-free reliability against plug-in on the two shallow samples, so it is genuinely noisier and not merely less depth-tracking. That was worth refusing to bury, and it is now established on an axis that gives no credit for tracking depth. Second, the cost is **bounded** — 0.898–0.959 is far from noise — and it is the only remaining axis on which Chao–Shen loses. Separately, plug-in retaining 0.971–0.973 depth-free reliability is itself a result for D3: the plug-in metric is not *purely* a depth readout even where 96–98% of its rank variance is depth-correlated, so there is real structure for the partial-correlation fallback to work with.

*Retired: the CV half of criterion 4 ($SD/\text{mean} \ge 0.02$).* $CV$ is a ratio-scale statistic and entropy in bits has no meaningful zero. The origin is set by the size of the gene universe ($\log_2 K$), a property of the reference (D5) rather than of the tissue; enlarging the universe shifts every $H$ by a near-constant and changes the $CV$ while changing nothing biological. The mean therefore has no interpretation as a unit and $SD/\text{mean}$ has none either. $IQR$ in bits is on the scale the metric is actually read on and is the defensible half. This was written into A0 without that being noticed, and the earlier A3 write-up reported only the $CV$ verdict, which made criterion 4's failure look like a property of Chao–Shen rather than of the statistic chosen to test it.

Under $IQR \ge 0.10$ alone, criterion 4 **passes for every estimator on every sample** — the minimum across all twelve cells is Chao–Shen's 0.1645 on sample1, against the 0.10 floor. Two verdicts flip on sample1 (Chao–Shen $CV = 0.0126$, $IQR = 0.1645$; Miller–Madow $CV = 0.0182$, $IQR = 0.1887$ — both were failing on $CV$ alone while passing $IQR$ comfortably). The honest reading is that criterion 4, evaluated with the defensible statistic, **carries no information at these thresholds**: it does not separate the candidates at all. It remains a genuine floor against a rarefaction-style collapse — rarefaction's $IQR$ would have to be checked to confirm it fails, its documented $SD = 0.0898$ makes that near-certain — but it is not evidence for or against any of the three corrections.

**Net effect on the A3/A4 picture.** Chao–Shen's standing improves and no verdict is manufactured. Criterion 4 no longer counts against it (it never should have). Criterion 3's rank clause no longer counts against it (it was scoring depth). Criterion 3's magnitude half still fails for **every** estimator on every sample, plug-in included, so it does not separate them either. What remains genuinely discriminating is criterion 1, which Chao–Shen passes only on sample21, and the descriptive precision cost above.

**Where this leaves Stage A5.** Chao–Shen is unambiguously the best of the three corrections on every axis that was measured — depth decoupling, bias removal under thinning, and the `percent.mt` association — and it is the only candidate that clears any of the pre-registered bounds. ## D3 — Entropy–depth & covariate QC and stemness correlation tests
**Script:** `R/entropy_correlation.R`, `R/quality_confound.R` (called from `analyze_entropy.R`, `diagnose_entropy_scaling.R`, `analyze_stemness.R`)
**Decision:** Both parametric Pearson correlation ($r$) and non-parametric Spearman rank correlation ($\rho$) are computed alongside two-sided $p$-values, log10 $p$-values, 95% confidence intervals, and spot sample size ($N$):
1. In `analyze_entropy.R`: evaluates correlations for both entropy baselines (`entropy_raw_plugin`, `entropy_spanorm_plugin`, D2) against sequencing depth (`nCount`, `nFeature`) and the metabolic covariate `percent.mt`, outputting results to `results/statistical_tests/<sample_name>_entropy_correlations.csv` and a 6-panel publication scatterplot. `percent.ribo` is not a target because ribosomal probe counts are identically zero across the cohort (D2, D6).
2. In `analyze_stemness.R`: evaluates biological correlation between each entropy column and `Stemness_Score1`, outputting results to `results/stemness_analysis/<sample_name>_stemness_correlations.csv` and `_spatial_comparison.png`.
3. In `analyze_stemness.R`, immediately after the stemness correlation: a **spot-quality confound control** (`run_quality_confound_check()` in `R/quality_confound.R`), run before any entropy–stemness association is treated as biological. The mechanism it exists to exclude: a degraded, high-MT spot has flatter, more ambient-like non-MT signal, which reads as higher transcriptional diversity, and shallow spots are the high-MT ones (cohort $\rho = -0.41$ between depth and MT, Stage 0) — so an entropy–stemness association could be entirely quality-driven. The check is metric-agnostic: it runs on whichever entropy columns are present and assumes nothing about how they were estimated. It has three parts. (a) *Covariate correlations of the score itself* — `Stemness_Score1` against `percent.mt`, `nCount` and `nFeature`, written to `results/stemness_analysis/<sample_name>_quality_confound_covariates.csv` together with the same correlations for every entropy metric. (b) *Partial correlation* of each entropy metric against `Stemness_Score1` controlling for `percent.mt`, for $\log(nCount)$, and for both, in Pearson and rank (Spearman) form, written to `_quality_confound_partial.csv`. Both variables are regressed on the covariates via `stats::lm.fit` and the residuals correlated; significance uses $t = r_{xy \cdot z}\sqrt{(N-2-k)/(1-r^2)}$ on $N - 2 - k$ degrees of freedom and the CI the Fisher $z$ transform with $SE = 1/\sqrt{N-3-k}$ ($\sqrt{1.06/(N-3-k)}$ for the rank version), where $k$ is the rank of the covariate design. (c) *Subset sensitivity*, written to `_quality_confound_subsets.csv`: the zero-order correlations recomputed on the clean spots (`percent.mt < 10`), on their complement, and within each quartile of `percent.mt`. A four-panel figure (`_quality_confound_plot.png`) shows score vs `percent.mt`, entropy vs `percent.mt`, entropy vs score coloured by `percent.mt`, and the residual–residual scatter behind the partial correlation.
All correlation statistics reported anywhere in the project — zero-order, subset and partial — come from a single helper, `pair_correlation_stats()` in `R/entropy_correlation.R`, so the estimate, exact $p$, log10 $p$ and CI conventions cannot drift between tables.
All summary CSV outputs store exact unfloored double-precision floats for `Pearson_p` and `Spearman_p`. Both correlations carry log10 $p$-values computed via Student's $t$ cumulative distribution in log space ($\log_{10}(p) = \log_{10}(2) + \frac{\text{pt}(-|t|, \text{df}, \text{log.p = TRUE})}{\ln(10)}$) to eliminate saturation at `0.00e+00`. Pearson 95% CIs are derived from `cor.test`; Spearman 95% CIs use Fisher $z$-transformation with the Bonett–Wright standard error $\text{SE} = \sqrt{1.06/(N-3)}$.
**Rationale:** Evaluating both Pearson and Spearman metrics captures linear and monotonic associations while reporting exact unfloored $p$-values for meta-analysis across the 16-sample cohort. The confound control is kept as a standing gate rather than a one-off: the depth and `percent.mt` couplings are properties of the estimator as much as of the tissue, so every candidate entropy metric has to clear it before its stemness association is read as biology, and the gate has to be re-run whenever the metric changes.
**Alternatives considered / rejected:** Storing formatted character strings in CSVs was rejected because it saturated small $p$-values at `"0.00e+00"`, preventing quantitative ranking and meta-analytic pooling. `ppcor::pcor.test` was rejected for the partial correlations: it computes the same residualisation-based quantity, and adding a package to the pinned environment for ~20 lines of base-R arithmetic is not worth the dependency. Using `percent.mt < 10` as the only subset check was rejected as too weak to discriminate — sample1 has a median `percent.mt` of 3.36% and the cut removes only 1.44% of spots, so the "clean subset" is very nearly the full set; the quartile strata are what make part (c) informative. Regressing on raw $nCount$ rather than $\log(nCount)$ was rejected because depth is right-skewed and enters the support ceiling logarithmically, so the linear covariate under-adjusts.
**Status:** implemented (machinery); **results pending** — every sample1 statistic previously recorded here was measured on the rarefied metric that D2 removed, and has been struck rather than carried forward under a new label. The tables are regenerated by the next cohort run.
**Review notes:** Refactored `calculate_entropy_correlations()` in `R/entropy_correlation.R` to support multiple entropy columns, numeric double columns, log10 $p$-values, and Fisher-z Spearman CIs. Added `R/quality_confound.R` and wired `run_quality_confound_check()` into `analyze_stemness.R`. The per-pair statistics block was extracted out of `calculate_entropy_correlations()` into `pair_correlation_stats()` so the confound tables reuse it rather than reimplementing the CI and log10 $p$ conventions; the `_entropy_correlations.csv` and `_stemness_correlations.csv` outputs are numerically unchanged by that extraction.

Rarefaction and regression adjustment are different corrections for the same depth confound, and they agreed — which suggests the depth confound, rather than the estimator, is what was hiding the association. Whatever replaces the current baselines should reproduce that agreement. **That requirement now has a pre-registered form** — see "Pre-registered for Stage C" in D2, item 2, which fixes the tolerance (agreement in sign, difference $\le 0.10$) and the consequence of failure before Stage C produces a stemness number. Its metric-level analogue, which needs no `Stemness_Score1`, was measured at Stage A5a.

## D5 — Cohort Gene Universe
**Script:** `build_gene_universe.R` (calls `R/gene_universe.R`)
**Decision:** The cohort gene universe is constructed across all 22 Visium samples by identifying all features with at least 1 count in at least 1 on-tissue spot in any sample, then excluding the retired `DEPRECATED_ENSG*` probe rows (`results/cohort_qc/gene_universe.csv`). Features in this universe are loaded via `load_gene_universe()` in `R/gene_universe.R` and used to filter raw matrices prior to per-sample filtering. Matching against a `Seurat` object is done on Seurat-sanitized names (`sanitize_feature_names()`), because `CreateSeuratObject()` rewrites underscores to dashes in feature names.
**Rationale:** Stage 0 chemistry verification demonstrated that all 22 samples share identical probe chemistry (Visium V5 Slide, CytAssist 11mm grid, 37,082 GRCh38 feature rows). Across the entire cohort of 22 samples:
- **19,015 features** (51.28%) carry $\ge 1$ count in $\ge 1$ sample on-tissue.
- Of those, **480 features** are retired `DEPRECATED_ENSG*` probe rows carrying 0.85% of cohort counts. They are excluded from the universe: they are artefacts of panel revision, not interpretable gene-level measurements.
- The gene universe is therefore **18,535 features** (49.98% of the grid), of which 18,532 are distinct symbols — three symbols appear twice in the GRCh38 feature list, and `make.unique()` renames the second copy in the loaded object but not in the universe file, so that copy is dropped.
- **18,067 features** (48.72%) are structurally zero across all 22 samples because no probe in the CytAssist Human Transcriptome panel targets them.
- **18,453 universe features** (99.56%) are detected in all 22 samples.
Because the probe panel is identical by construction, the gene universe is fully deterministic without requiring ad-hoc union rules or union-negotiation across samples. Filtering to this universe removes uninformative zero-probe rows upfront, standardizing the feature space across the cohort.
The universe is built over **all 22 samples, including the 6 excluded by D6**, and `build_gene_universe.R` calls `all_samples()` rather than `cohort_samples()` for that reason. This is deliberate. The union is permissive by design, so features contributed only by the degraded samples are rare everywhere and contribute negligibly to entropy; rebuilding on 16 would shrink the feature space and invalidate the sample1 figures recorded in D1 and D2 for no measurable gain. The gene universe is reference data, not a biological result, and is the one place in the pipeline where the full slide set is used.

**Alternatives considered / rejected:** Retaining all 37,082 GRCh38 rows was rejected because it distorts gene retention QC denominators and inflates memory consumption. Defining the universe per-sample was rejected because it causes inconsistent feature sets across samples in downstream cohort comparisons. Retaining the `DEPRECATED_ENSG*` rows was rejected on interpretability grounds. Rebuilding the universe on the 16-sample D6 cohort was rejected per the paragraph above.
**Status:** implemented
**Review notes:** Implemented `build_gene_universe.R` and `R/gene_universe.R`. Emitted `results/cohort_qc/gene_universe.csv` with gene IDs, gene names, cohort total counts, per-sample detection frequencies, and the `is_deprecated_probe` flag.

- `sample19`: mean spot MT = 10.80%, total counts = 133.4M, median depth = 9,185
- `sample20`: mean spot MT = 16.84%, total counts = 36.6M, median depth = 2,995

The remaining 16 samples form the primary analysis cohort (`sample1`, `sample4`, `sample5`, `sample6`, `sample7`, `sample8`, `sample9`, `sample10`, `sample11`, `sample13`, `sample14`, `sample15`, `sample17`, `sample18`, `sample21`, `sample22`), exhibiting clean transcriptomes with mean spot $\text{\%MT}$ between 3.42% and 8.73%.

**Space Ranger Version Note:**
All 22 raw sample HDF5 files contain the embedded root attribute `software_version = "spaceranger-2.0.1"`, whereas the GEO series metadata annotation indicates Space Ranger 4.0.1. We explicitly note this metadata discrepancy: all upstream probe alignment, demultiplexing, count matrix generation, and fiducial image alignment files were generated using Space Ranger 2.0.1 per the file-level attributes embedded in every sample HDF5.

**Rationale:** High mitochondrial percentage in Visium FFPE spatial transcriptomics indicates cellular membrane lysis, loss of cytoplasmic mRNA, and severe tissue degradation. Degraded spots lose structured, cell-type-specific transcriptional programs and present flat, ambient-like non-mitochondrial RNA profiles. Flatter distributions mechanically inflate any diversity estimator, so pervasive degradation acts as a profound technical confounder on entropy regardless of how it is estimated. Establishing an explicit quality cutoff at mean spot $\text{\%MT} < 10\%$ before running cross-sample biological inference protects against false-positive entropy–stemness correlations driven by tissue degradation.

**Alternatives considered / rejected:**
1. *Post-hoc sample exclusion based on stemness correlation:* Strongly rejected. Excluding samples after observing their biological correlation produces severe selection bias and invalidates statistical inference. Quality exclusion must be frozen upfront based strictly on orthogonal technical quality metrics (Stage 0 %MT).
2. *Exclusion based on sequencing depth alone:* Rejected because several moderate-depth samples (e.g., sample4, sample21) have low mitochondrial read percentages ($\text{\%MT} \le 8.3\%$) and intact spatial tissue morphology, yielding valid biological data.
3. *Ad-hoc spot-level MT trimming without sample exclusion:* Rejected because heavily degraded samples (where >50% of spots have high MT and total sample MT is elevated) suffer from pervasive ambient background contamination across all capture spots.

**Second gate — spot retention.** The spot QC floor in D1 drops each sample's shallow tail, and that tail is not the same size everywhere. Dropped spots are the shallow ones, which are spatially clustered rather than scattered, so each sample enters Stage 4 with a differently-holed hex lattice; a sample that has lost a third of its tissue area is not directly comparable to one that lost none.

A minimum retention of **60% of on-tissue spots** (`COHORT_MIN_RETENTION_PCT` in `R/cohort.R`) is therefore frozen *before* the cohort run, for the same reason the %MT threshold is: a retention floor chosen after seeing entropy–stemness correlations is a selection-bias generator, which rejected alternative 1 forbids. `check_cohort_retention.R` applies it against the per-sample QC tables after the run and writes `results/cohort_qc/retention_gate.csv`.

Under the current $nCount \ge 500$ / $nFeature \ge 250$ floors (D1) the gate is a guard rather than a live discriminator: every cohort sample is expected to retain close to 100% of its on-tissue spots. It bit hard under the previous revision, where the QC floor was pinned to the rarefaction depth $D = 2000$ and retention ranged from 99.6% (sample1) through 81.5% (sample4) to 68.1% (sample21) — uneven tissue loss that was one of the reasons rarefaction was set aside (D2). The floor stays frozen at 60% so that it is already in place if a future estimator reintroduces a depth-dependent gate.

## D7 — Spatial neighbourhood construction & spatial autocorrelation
**Script:** `R/spatial_neighbors.R` (built at Stage B1; consumed by Stage B2 and the spatial inference)
**Decision:** Spatial adjacency between Visium spots is constructed directly from the capture-array lattice rather than from imaged pixel coordinates. Visium spots sit on a hexagonal lattice indexed by `array_row` and `array_col`, in which `array_col` increments by 2 within a row and adjacent rows are offset by 1, so the six neighbours of a spot at $(r, c)$ are exactly $(r, c\pm2)$, $(r-1, c\pm1)$ and $(r+1, c\pm1)$. `hex_neighbor_graph()` builds the symmetric sparse 0/1 adjacency from those offsets; `hex_neighbor_graph_from_seurat()` reads `array_row` / `array_col` out of the object metadata, where D1 has been writing them since before there was a use for them. `row_standardise()` produces the weights matrix $W$ with rows summing to 1, leaving isolated spots as all-zero rows.

Moran's I is computed by `morans_i()` in its general form,
$$I = \frac{n}{S_0} \cdot \frac{z^{\top} W z}{z^{\top} z}, \qquad S_0 = \sum_{ij} w_{ij},$$
with $z$ the centred variable, and significance assessed by permutation (999 permutations by default, seeded) using the $(n_{\text{extreme}} + 1)/(n_{\text{perm}} + 1)$ two-sided construction. `morans_i_table()` applies it across several metadata columns and `neighbor_summary()` reports the degree distribution of the lattice graph as a geometry sanity check.

**Rationale:** Building the graph from lattice indices removes a free parameter that would otherwise have to be defended. A $k$-nearest-neighbour or distance-threshold graph on the imaged coordinates requires choosing $k$ or a radius, and no principled choice exists; here the geometry is known exactly and there is nothing to tune. It also degrades correctly where the D1 QC floors have removed spots: a spot next to a hole simply loses a neighbour, whereas a kNN graph silently promotes a more distant spot to "nearest" and manufactures adjacency across the gap.

The $n/S_0$ factor is carried explicitly rather than cancelled. Under row-standardisation $S_0$ equals the number of *non-isolated* spots, so the factor reduces to 1 only when every spot has at least one neighbour — true on an intact lattice, not guaranteed after QC. Isolated spots keep an all-zero weights row, so they contribute nothing to the numerator while still contributing their variance to the denominator; that is the conservative direction, since an isolated spot cannot manufacture autocorrelation.

The permutation null is used rather than the analytic normal approximation because that approximation assumes an approximately normal variable, and `percent.mt` and the entropy metrics are not. What the permutation tests is worth stating precisely for the write-up: spot values are reshuffled over a *fixed* lattice, so the null is "these values are arranged at random over this tissue's geometry". The geometry, holes included, is held constant and is not itself under test.

**Alternatives considered / rejected:** `spdep` was rejected for the same reason `ppcor` was rejected in D3 and `scuttle` was dropped in D2 — it pulls `sf`, and therefore GDAL, GEOS and PROJ, on the order of 300–500 MB of system libraries, to provide one statistic that is roughly forty lines of sparse arithmetic. The project already runs on a 15.1 GB machine that needed a blocked kernel to fit SpaNorm; adding a heavyweight geospatial stack for Moran's I is not a trade worth making, and the implementation is validated instead (below). Neighbour graphs built from imaged pixel coordinates by kNN or distance threshold were rejected per the rationale above. The analytic normality-assumption $p$-value was rejected in favour of permutation.

**Status:** draft — the machinery is implemented and tested; no *result* has been produced with it yet. Stage B2 (Moran's I on the technical covariates, to test whether SpaNorm's spatial spline has anything to act on) and the spatial inference that this entry will eventually document are both pending. The rationale above may be extended but should not need revising.

**Review notes:** Validated by `tests/test_spatial_neighbors.R` (33 checks, run as `Rscript tests/test_spatial_neighbors.R`). Moran's I is checked against an independent naive $O(n^2)$ double-loop transcription of the textbook formula, which shares no code with the sparse implementation — including on a graph containing an isolated spot, the case where the $n/S_0$ factor does not cancel and where the shortcut form $z^{\top}Wz / z^{\top}z$ gives the wrong answer. The lattice tests assert the six offsets explicitly on an interior spot rather than only checking that its degree is 6, since a transposed or sign-flipped offset set would still produce degree 6; they also assert that removing a spot lowers its neighbours' degree by exactly one and that a distant spot stays isolated rather than being attached to its nearest neighbour, which is the specific failure a kNN graph would exhibit. Behavioural checks cover a smooth gradient ($I = 0.98$, $p \le 0.001$), an alternating pattern ($I < 0$) and random noise ($|I| < 0.15$, $p > 0.05$), plus reproducibility under a fixed seed and `NA` handling. One implementation bug was found and fixed by these tests: `Matrix::Diagonal() %*% adj` silently drops dimnames, so row-standardised weights could not be indexed by spot id.
